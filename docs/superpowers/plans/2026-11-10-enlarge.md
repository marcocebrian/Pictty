# Enlarge Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An Enlarge 2× / 4× edit in Pictty, run by BHI RealPLKSR on Core ML, for pictures of 8 MP or less as cropped.

**Architecture:** A Core ML model built by a script in `Models/`; pure, testable geometry (eligibility, tiles, seam weights, face feather) in `PicttyCore/Enlarge.swift`; the runner `NeuralUpscaler` in the app, modelled on `NeuralDenoiser`; Enlarge as the last pixel edit in the existing edit pipeline (adjustments → crop → enlarge → turn), with a toolbar button and strip like the compare picker.

**Tech Stack:** Swift 6 / AppKit / SwiftUI, Core ML (`.cpuAndGPU`), Vision (`VNDetectFaceRectanglesRequest`), Python 3.12 + coremltools 9 + spandrel for the conversion (study venv at `/tmp/upscale-study/venv`).

**Spec:** `docs/superpowers/specs/2026-11-10-enlarge-design.md`

## Global Constraints

- Limit: the picture as cropped must be ≤ 8 000 000 pixels (`EnlargeRule.maxPixels = 8_000_000`); not offered for HDR pictures.
- Factors: 2 and 4 only. 2× = the 4× result shrunk by half with `Resampler.render(..., kernel: .lanczos, linearLight: true)`.
- Order: original → adjustments (incl. noise reduction) → crop → enlarge → turn/mirror.
- Core ML compute units `.cpuAndGPU` (Neural Engine measured slower). Model output must match PyTorch ≥ 45 dB PSNR on the study inputs.
- Licence: CC-BY-4.0, credit line "4xBHI_realplksr_dysample_real by Philip Hofmann (github.com/Phhofm/models)"; shipped as `Upscale-LICENSE.txt`.
- Commits as the configured git user (Marco Cebrián Muiño), **no** Co-Authored-By / Claude trailer. `Resources/es.lproj/Localizable.strings` is gitignored: edit it, don't commit it.
- Every user-visible string goes through `L(...)` / SwiftUI localised text, in English and Spanish.

## Review Focus

1. **A crop or slider change, or moving to another picture, while the network runs** — the stale result must be dropped, never shown on another picture or edit. Owned by Task 4 (ticketed results, check after `goto`/`next` and a slider change mid-run).
2. **Memory at the top end** (8 MP × 4 = 128 MP): the output must be written tile by tile into one 8-bit (16-bit for 16-bit sources) bitmap, never a whole-picture Float buffer (2 GB). Owned by Task 3 (peak memory printed by the dev hook for an 8 MP input, must stay < 1.5 GB above the app's baseline).
3. **Pictures smaller than a tile, or not a multiple of it** (e.g. 300×200, 1001×777): edges padded by reflection, output exactly `w×f, h×f`. Owned by Task 2 (tile plan tests) and Task 3 (dev hook on a 300×200 PNG).
4. **Transparency** (PNG with alpha, rounded crop): alpha enlarged with Lanczos and put back, rounded corners stay round. Owned by Task 3.
5. **A crop that grows past 8 MP after Enlarge was turned on** — Enlarge turns off with a toast instead of running on 30 MP. Owned by Task 4.

**Interfaces:**
- Produces: model input `"input"` Float32/Float16 `[1, 3, T+2·O, T+2·O]`, output `"output"` `[1, 3, 4(T+2·O), 4(T+2·O)]`, values 0…1 encoded RGB. The tile size `T` and margin `O` chosen in Step 3 are written into the model's `userDefinedMetadata` as `"tile"` and `"margin"` (strings), so the app reads them instead of hard-coding.

- [ ] **Step 1: Write the script from the study.** Port `/tmp/upscale-study/scripts/convert.py` (DySample constant grid + plain sizes, GroupNorm `x / 64` with `eps / 64²`) and `build_mixed.py` (`FP16ComputePrecision(op_selector=…)` keeping 17×17 convs, `(64, 64, 3, 3)` attention convs and the ops after the last `batch_norm` in 32-bit) into one script: `make-upscale-model.py <weights.safetensors> <out.mlpackage> [--tile T] [--keep conv17,attn,tail]`. Header docstring in the style of `make-denoise-model.py`: where the weights come from (`gh release download 4xBHI_realplksr_dysample_real -R Phhofm/models`), how to install (`uv pip install torch coremltools spandrel safetensors`), why each rewrite exists, measured speed.
- [ ] **Step 2: Write the check.** `Models/make-upscale-model.py --check <mlpackage>`: runs the four inputs in `/tmp/upscale-study/work/small/in/p*.png` through Core ML (`CPU_AND_GPU`, reflect padding, same tiling) and PyTorch MPS, prints PSNR between them per photo and seconds per input MP. Pass = every PSNR ≥ 45 dB.
- [ ] **Step 3: Measure the acceleration options**, one row each, same check: (a) the study's mixed model at T=512 (baseline, expect ~49 dB, ~1.7 s/MP); (b) T=768 and T=1024; (c) keep only `tail` + `conv17` in 32-bit; (d) (c) plus DySample made exact in half precision — compute `coords` as `2·(grid + offset)/normalizer − 1` with `grid/normalizer` folded into one fp32 constant and only the small `offset/normalizer` term in fp16; (e) best of the above + `linear_quantize_weights` 8-bit. Keep the fastest variant with every PSNR ≥ 45 dB and no NaN; record the table in `Models/README.md`.
- [ ] **Step 4: Build `Models/Upscale.mlpackage`** with the chosen settings and add the `tile`/`margin` metadata. Expected size ≈ 16 MB (≈ 8 MB with 8-bit weights).
- [ ] **Step 5: Licence, README, build.sh.** `Models/Upscale-LICENSE` = CC-BY-4.0 text + the credit line. Run `./build.sh` and check `build/Pictty.app/Contents/Resources/Upscale.mlmodelc` and `Upscale-LICENSE.txt` exist.

### Task 2: Enlarge geometry in PicttyCore

**Files:**
- Create: `Sources/PicttyCore/Enlarge.swift`
- Test: `Tests/PicttyCoreTests/EnlargeTests.swift`

**Interfaces:**
- Produces:
  - `public enum EnlargeRule { static let maxPixels = 8_000_000; static let factors = [2, 4]; static func refusal(pixelSize: CGSize, isHDR: Bool) -> Refusal?; static func outputSize(_ size: CGSize, factor: Int) -> CGSize }` with `public enum Refusal: Equatable { case tooLarge, hdr }`.
  - `public struct EnlargeTile: Equatable { let source: CGRect /* tile + margin, may reach outside the picture: reflect-pad */; let keep: CGRect /* the part written, in source px */ }` and `public static func EnlargeRule.tiles(width: Int, height: Int, tile: Int, margin: Int) -> [EnlargeTile]`.
  - `public static func EnlargeRule.faceWeights(faces: [CGRect], width: Int, height: Int) -> [Float]` — per output pixel 0…1, 1 = keep the model's pixel, 0 = use Lanczos; faces in normalised Vision coordinates (origin bottom-left); ellipse inscribed in each face rect grown by 25 %, feathered over 25 % of the face's shorter side with a smoothstep.

- [ ] **Step 1: Write the failing tests**
  - `testRefusesOverEightMegapixels`: `refusal(3266×2450 (8.0 MP), false) == nil`; `refusal(3500×2450, false) == .tooLarge`; `refusal(1000×1000, true) == .hdr`.
  - `testOutputSize`: `outputSize(1500×1000, 4) == 6000×4000`, `(1001×777, 2) == 2002×1554`.
  - `testTilesCoverEveryPixelOnce` for (1001, 777, 512, 32) and (300, 200, 512, 32): the `keep` rects are disjoint, their union is the picture, each `source` = `keep` grown by `margin` on every side and has the same size `tile + 2·margin` (smaller pictures: one tile).
  - `testFaceWeights`: no faces → all 1; one face at (0.4, 0.4, 0.2, 0.2) on 100×100 → weight at the centre `== 0`, at a corner `== 1`, monotonic along a line from centre to corner.
- [ ] **Step 2:** `swift test --filter EnlargeTests` → FAIL (no `EnlargeRule`).
- [ ] **Step 3:** Implement in `Sources/PicttyCore/Enlarge.swift`.
- [ ] **Step 4:** `swift test --filter EnlargeTests` → PASS; `swift test` → all pass.

### Task 3: NeuralUpscaler

**Files:**
- Create: `Sources/Pictty/Render/NeuralUpscaler.swift`
- Modify: `Sources/Pictty/App/DevScript.swift` (hook `upscalefile <in> <out> <factor>`)

**Interfaces:**
- Consumes: `EnlargeRule.tiles`, `EnlargeRule.faceWeights` (Task 2); model metadata `tile`/`margin` (Task 1); `Resampler.render`.
- Produces: `final class NeuralUpscaler: @unchecked Sendable { static let shared; var isAvailable: Bool; func warmUp(); func enlarge(_ image: CGImage, factor: Int, cancelled: () -> Bool, progress: ((Double) -> Void)?) -> CGImage? }` — synchronous, call off the main thread; nil when cancelled or unavailable. Output size = `EnlargeRule.outputSize`, same colour space and bit depth class as the input (8-bit in → 8-bit out, else 16-bit).

- [ ] **Step 1:** Write `upscalefile` in `DevScript`: decode `<in>` with `ImageDecoder.full`, `enlarge` on a background queue, write PNG to `<out>`, print `upscale <w>×<h> → <W>×<H> in <s> s, peak <GB>` (peak from `task_info` resident size).
- [ ] **Step 2: Implement** following `NeuralDenoiser`: lazy `MLModel` load, `warmUp()` on a utility queue; input drawn into an RGBA float context in the image's colour space (extended sRGB for non-RGB), per tile reflect-padded `MLMultiArray` (Float16 if the model input is), outputs written straight into one output `CGContext` (no whole-picture float buffer). Seams: none needed because `keep` rects are disjoint and margins are cut off (as the study did). Safeguard per tile: non-finite values, or mean absolute difference > 0.08 from the Lanczos 4× of the same tile → that tile's Lanczos. Faces: `VNDetectFaceRectanglesRequest` on the input; if any, blend `out = lanczos + w·(model − lanczos)` with `faceWeights`. Alpha: Lanczos-enlarged and re-applied. Factor 2: `Resampler.render(full4x, … width: w*2, height: h*2, kernel: .lanczos, linearLight: true)`. `cancelled()` checked between tiles.
- [ ] **Step 3: Verify against PyTorch.** Build (`./build.sh`), run `PICTTY_SCRIPT="1 upscalefile /tmp/upscale-study/work/small/in/p3.png /tmp/enl-p3.png 4; 30 quit"` on the built app, then compare `/tmp/enl-p3.png` with `/tmp/upscale-study/work/small/out/4xBHI_realplksr_dysample_real-3.png` in the study venv: PSNR ≥ 45 dB outside faces; time ≤ the Task 1 figure × 1.2.
- [ ] **Step 4: Edge inputs** (Review Focus 2–4): a 300×200 PNG with transparency → 1200×800, alpha preserved at the corners; an 8 MP picture (`photos/p1.jpeg` shrunk to 3264×2448) → peak < 1.5 GB above baseline; a portrait with a face (any from `~/Pictures` the hook finds, or `p1`'s person crop) → face visibly plain, the rest detailed (look at the PNG).
- [ ] **Step 5: Commit** "Enlarge: NeuralUpscaler, tiles on Core ML, faces kept plain".
